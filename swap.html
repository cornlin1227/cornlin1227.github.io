01DIAGNOSIS / 问题诊断

用户想兑换，
产品却先让他
理解产品。

旧版首先呈现品牌叙事、版本切换、链切换与大量导航。真正的交易入口被放在第二步，协议差异又继续侵入交易过程，视觉氛围强烈，但任务层级不清楚。

01 / DETOUR营销首页
挡在交易之前

核心用户已经带着明确目标而来，却需要先经过展示页再进入 Swap。

02 / NAVIGATION导航承载
过多产品概念

版本、链、市场、工具与文档同时争夺注意力，用户先识别系统，再寻找任务。

03 / PROTOCOL协议结构
暴露给用户

RUNES、BRC20、ARC20 与不同支付通道分散在多个入口中。

04 / NOISE次要信息
持续占据首屏

价格图、持币榜、个人记录与全站记录同时出现，削弱兑换本身。

视觉冲击≠任务清晰产品需要从“解释系统”转向“帮助完成交易”。
02STRATEGY / 重构策略
THE REDESIGN WAS NOT A RESKIN

先减法，
再重组。

方案从信息结构与关键路径入手：删除不必要的前置步骤，把重复信息合并，把低频信息收起，并把协议选择放回最符合用户心智的位置。

REMOVE

删除

取消原首页、V1 独立切换与顶部链切换，让用户进入产品后直接开始兑换。

HOME → SWAP
MERGE

合并

个人记录与全站记录合并为一个记录区域；通道、账户与余额归入资产视图。

2 RECORDS → 1 VIEW
HIDE

收起

价格图、交易记录、服务费和网络费按需展开，默认首屏只保留决策必需信息。

ALWAYS ON → ON DEMAND
RELOCATE

归位

协议类型进入代币选择层，V1 退回支付方式，复杂性被放到最恰当的决策节点。

SYSTEM FIRST → TASK FIRST

AFTER打开即兑换→按需选择代币与支付方式
MULTI-ROUTE EXPERIENCE AUDIT

改版发生在整条产品路径，
而不只发生在首页。

从两个站点的产品结构和第一阶段升级方案出发，逐页拆解交易、选币、流动性、发现、奖励、资产和历史记录。每一页都围绕同一个原则：主任务前置，复杂信息按需出现。

01 / SWAP

交易路由

BEFORE

营销首页先行；图表、榜单、个人记录与全站记录同时争夺首屏。

AFTER

打开即 Pay / Receive；图表、记录、服务费与网络费根据状态展开。

02 / TOKEN SELECTOR

选币与网络

BEFORE

协议和链切换散落在导航及交易框之外，用户先理解系统结构。

AFTER

RUNES、BRC20、Stablecoin、Fractal、ARC20 归入选币层，并标注协议类型。

03 / POOLS

流动性路由

BEFORE

池子、个人记录、全站记录与网络费长期展开，阅读负担持续存在。

AFTER

池子与记录可收起；筛选、注入、兑换和费率说明使用统一交互语言。

04 / EXPLORE

市场发现

BEFORE

市场、文档和奖励入口分散，表格操作大量依赖重复文字按钮。

AFTER

文档并入 Explore；Pools 与 LP 收益独立分组，周期筛选和操作图标统一。

05 / REWARDS

奖励路由

BEFORE

推荐收益、等级、任务与完成状态缺少清晰的阅读先后关系。

AFTER

收益概览、佣金等级、任务进度形成连续纵向路径，状态反馈更明确。

06 / ASSETS & HISTORY

资产与记录

BEFORE

通道、V1 账户、钱包余额和多种交易记录分散在不同位置。

AFTER

统一资产总览；记录去除冗余 txid，并按 V1 / V3 给出对应状态与去向。

05SYSTEM IN PRACTICE / 系统化落地

不是只改
一个 Swap 框。

同一套层级、表格、状态与反馈语言被扩展到 Explore、Rewards、资产管理和全局提示，使复杂金融信息在不同页面仍保持一致。

BACKGROUND MOTION / 动态品牌层

背景持续流动，
界面保持稳定。

产品背景不是静态渐变：暗紫与蓝色光场以低频率缓慢移动，网格和粒子提供空间深度，关键区域再用局部高光聚焦。动态承担品牌氛围，交易和资产信息始终保持清晰、稳定。

  • 02微弱网格维持 Web3 空间感
  • 03高光只服务于关键操作区域

WHAT THIS PROJECT PROVED

Web3 产品的专业感，
不是展示更多复杂性。

真正的升级，是让协议、通道、费用和状态在用户需要时出现，在不需要时退后。视觉改版只有和信息架构、交互路径以及真实业务规则一起发生，才会转化为更好的产品体验。
